Active-Passive vs Active-Active Clustering

How multiple servers provide availability and traffic handling, and where state consistency becomes the hard part.

Active-Passive

  • One server/group is active and handles production traffic.
  • Another is passive/standby and normally serves no production traffic.
  • If the active node fails, the passive node is promoted.
Load Balancer→Active AorPassive B

How does passive know?

A health monitor checks heartbeats or health endpoints. If failure is detected, B is promoted.

Active-Active

  • Both servers are active and serve traffic.
  • A load balancer distributes requests.
  • If one fails, traffic is redistributed to the other.
Load Balancer→Server A+Server B

Big challenge: state consistency

If both servers independently maintain mutable state, concurrent writes can produce inconsistent views.

01

State consistency example

Multiple active nodes must agree on shared mutable state.

Example: A and B both start with balance ₹1000. A processes a ₹200 withdrawal and sees ₹800, while B still sees ₹1000. Shared state, sticky sessions with care, or a consistency mechanism is required depending on the architecture.
02

There is no universally better topology.

03

Split brain

A classic follow-up question.

Split brain occurs when two nodes both believe they are the active/primary node, often because communication between them fails.

  • Both may accept writes.
  • State can diverge or conflict.
  • Use quorum, fencing/STONITH, leases or a consensus-based coordination mechanism where appropriate.
Interview shortcut: Active-Passive prioritizes a simpler single-writer model but leaves standby capacity underused. Active-Active uses resources more efficiently and can scale traffic, but requires careful handling of state, routing, failover and split-brain scenarios.
