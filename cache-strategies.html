Cache Strategies

How different cache read/write strategies trade off latency, consistency, write performance and operational complexity.

01

What is a cache?

A temporary storage layer for frequently accessed data.

Why use it?

  • Lower response latency by serving data from memory.
  • Reduce load on databases and backend services.
  • Improve scalability and sometimes reduce infrastructure cost.

Key terms

Cache Hit
Requested data is found in the cache.
Cache Miss
Data is absent and must be fetched from the source.
TTL
How long an item remains valid in the cache.
Eviction
Removing entries when space is needed.
Consistency
Keeping cached data aligned with the source of truth.

02

Cache-Aside

Application owns cache reads and writes.

  1. Application checks the cache.
  2. On a miss, it reads from the DB.
  3. Application stores the result in cache.
  4. On a write, update the DB and invalidate/update the cache.

Good default for many read-heavy systems.

03

Write-Through

Cache and DB are updated synchronously.

App
→
Cache
→
DB
  • Write goes through the cache.
  • Cache synchronously writes to the DB.
  • Read-after-write consistency is easier to reason about.

If DB update fails, the application must also roll back or invalidate the cache update.

04

Write-Back

Cache first, DB later.

  1. Write to cache first.
  2. DB is updated asynchronously later.

High write performance and fewer DB writes.

Cache/server failure before persistence can risk data loss; recovery and retry handling are important.

05

Read-Through

Cache owns loading data on a miss.

  1. Application asks the cache for data.
  2. On a miss, the cache fetches from the DB.
  3. Cache stores and returns the result.

Simplifies application logic because cache loading is centralized.

06

Refresh-Ahead

Refresh hot data before it expires.

  1. Cache predicts that a frequently used item is approaching TTL expiry.
  2. It refreshes the item before expiry.

Useful for hot data with predictable access patterns where cache misses are expensive.

07

Quick comparison

Choose based on the workload and consistency requirement.

Interview shortcut: Start with Cache-Aside as the common baseline. Then explain Write-Through when consistency matters, Write-Back when write latency matters, Read-Through when you want cache-owned loading, and Refresh-Ahead when hot data can be predicted.
